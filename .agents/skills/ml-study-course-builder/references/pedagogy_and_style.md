## 2. 필수 교수법 4원칙

### ① 기존 지식에 닻 내리기 (Spring ↔ ML 1:1 매핑)
새 ML 용어가 나오면 수학 정의부터 쓰지 말고 백엔드 개발 감각으로 먼저 번역한다.
- EDA → API 짜기 전 `SELECT * FROM table LIMIT 10`으로 DB 까보기
- 모델 학습 → `if-else`를 사람이 안 짜고 과거 데이터로 규칙 함수를 자동 생성
- 데이터 누수(Leakage) → 테스트 코드에 정답을 미리 박아놓고 통과했다고 착각하는 버그
- Train/Test 분할 → 로컬 테스트만 하고 운영 트래픽 검증 없이 배포하는 걸 막는 분리
- 피처 엔지니어링 → Raw DB 컬럼을 모델이 잘 먹도록 가공하는 DTO / 쿼리 프로젝션
- 평가지표(MAE, F1 등) → API p95 응답속도 같은 벤치마크 수치
- Pipeline → Spring Filter / Interceptor 체인 (전처리~예측 순서를 하나로 묶어 운영 일관성 보장)

### ② POE 방식 (Predict → Observe → Explain)
주요 코드 셀 바로 위에는 반드시 **`[실행 전 예측]`** 질문을 넣는다.
- 학습자가 코드 실행 전에 10초라도 머리로 먼저 예상하게 만든다.
- 예상과 실제 결과가 어긋날 때 이해도와 기억력이 가장 크게 올라간다.

### ③ 생산적 실패 (Productive Failure)
처음부터 정답 코드를 주지 않는다. **실무에서 초보가 꼭 밟는 버그를 일부러 터뜨리고** 왜 망했는지 눈으로 본 뒤 고친다.

#### 주제별 단골 함정 카탈로그 (데이터셋에 맞게 2~3개 선정)
- **회귀 (Regression):**
  1. 정답과 직결된 컬럼 포함(데이터 누수)
  2. 시계열 데이터를 랜덤 분할(미래 컨닝)
  3. 비선형 패턴(출퇴근 쌍봉 등)에 직선 모델(선형회귀) 적용
  4. 극단 이상치(Outlier) 때문에 RMSE만 폭등
- **분류 (Classification):**
  1. 불균형 데이터(예: 사기 1%, 정상 99%)에서 "전부 정상" 찍고 정확도(Accuracy) 99%에 속기 → Precision/Recall/F1 필요성 체감
  2. 결측치 채우기/스케일링을 `train_test_split` 전에 전체 데이터로 실행(전처리 누수)
  3. 기본 임계값 `0.5`만 써서 비즈니스 손실 발생 → Threshold 튜닝 체험
- **시계열 (Time Series):**
  1. 랜덤 셔플 분할로 미래 정보 누수
  2. 추세(Trend)가 있는데 트리 모델 외삽(Extrapolation) 한계 부딪히기
  3. 시차 변수(Lag feature) 만들 때 shift 방향 실수(미래값 참조)
- **군집 (Clustering):**
  1. 스케일링(단위 통일) 안 하고 K-Means 돌려서 큰 숫자 컬럼(연봉) 하나가 군집을 지배하는 버그
  2. `K`값 감으로 찍었다가 해석 불가능한 군집 나오기
- **텍스트 / NLP:**
  1. 불용어·HTML 태그·중복 문서 안 걸러서 쓸데없는 단어가 상위 특성 차지
  2. Test 문서를 포함한 전체로 TF-IDF/Tokenizer 학습(누수)

### ④ 1단계 = 1변경 = 1수치 (벤치마크 로그)
모든 실험 단계는 **딱 한 가지만 바꾸고** 평가지표가 몇에서 몇으로 변했는지 표로 기록한다.

## 3. 코드 해설 강화 규칙 (필수!)

학습자는 Python 기초만 알고 `pandas`/`scikit-learn` 문법이 익숙하지 않다.  
코드와 해설 사이를 위아래로 오가며 시선이 분산되지 않도록 **① 모든 코드 셀 내부에 인라인·상단 주석으로 줄별 동작과 Java/SQL 비유를 바로 적고**, **② 코드 셀 바로 아래에 `🔍 코드 뜯어보기` 블록**으로 SQL 번역 예시·핵심 원리·함정을 보충 설명한다.

1. **줄 단위/메서드 단위 동작 원리:**
   - 단순히 `# 그룹별 평균 계산`으로 끝내지 않는다.
   - 예: `df.groupby(["workingday", "hr"])["cnt"].mean().unstack(level=0)`라면
     - `groupby(["workingday", "hr"])` → SQL의 `GROUP BY workingday, hr`
     - `["cnt"].mean()` → 그 안에서 `AVG(cnt)` 계산
     - `.unstack(level=0)` → 세로로 길게 나온 결과를 `workingday`(0, 1) 컬럼 2개로 피벗(Pivot)해서 그래프 그리기 편하게 펼침
2. **Java / SQL 개발자 대응 비유 (해당되는 경우):**
   - `df[df["cnt"] > 100]` → SQL `WHERE cnt > 100` / Java `stream().filter(...)`
   - `lambda x: ...` → Java 람다 `x -> ...`
   - `df.agg(...)` → SQL `SELECT COUNT(*), AVG(cnt), MIN(cnt), MAX(cnt)`
   - `model.fit(X_train, y_train)` → 규칙 학습(빌드 타임) vs `model.predict(X_test)` → 추론 실행(런타임)
3. **자주 헷갈리는 파이썬 함정 1줄 팁:**
   - `df["col"]` (Series, 1차원) vs `df[["col"]]` (DataFrame, 2차원 — `sklearn` 입력은 항상 2차원!)
   - `inplace=True` 대신 재할당 권장 이유
   - `observed=False` 등 pandas 2.x 경고 방지 옵션 설명

*(단, 앞 셀에서 이미 상세히 설명한 기초 문법은 반복하지 말고, 새로 등장하는 문법과 핵심 로직에 집중한다.)*

## 4. 문체 규칙 (AI 말투 완전 금지)

### ❌ 절대 쓰지 말 것 (금지 표현 목록)
- `~는 ~를 전제로 하지 않는다`
- `~라고 해서 반드시 ~인 것은 아니다`
- `중요한 점은 ~라는 것이다` / `주목할 만한 점은`
- `다양한 관점에서 살펴볼 필요가 있다`
- `이번 섹션에서는 ~에 대해 알아보겠습니다` (교과서 서론)
- `매우 흥미로운 결과입니다` / `탁월한 선택입니다` (공허한 감탄)
- 추상적인 개념 정의를 3문장 이상 길게 늘어놓기

### ⭕ 이렇게 쓸 것
- **결론 먼저, 이유는 바로 뒤에 1~2문장.**
  - 예: "`casual`과 `registered`는 바로 지워야 한다. 둘을 더하면 정답(`cnt`)이 그대로 나오기 때문이다."
- **구체적 숫자·컬럼명·비유를 바로 꽂는다.**
  - 예: "평균만 보면 74대지만 `count`가 고작 3건이다. 로그 3줄 보고 운영 로직 짜는 거랑 똑같다."
- **발표 대본은 실제 개발자가 동료 앞에서 말하듯 구어체로 쓴다.**
  - 예: "저도 처음엔 컬럼 다 넣고 돌렸는데요, 점수가 99.9%가 나와서 '오 나 천재인가?' 했습니다. 근데 알고 보니 버그였어요."
